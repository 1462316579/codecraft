# 写作技能

## 适用场景
当前项目是写作项目：工作区是手机外部存储「AI小说」目录下的书籍脚手架（角色关联 / 小说资料 / 小说章节），不是容器内的源码仓库。

## 工作方式
- 读写一律用文件工具（`readFile` / `writeFile` / `editFile` / `list` / `search`）；没有 Bash、终端与构建工具，也不要尝试启动容器。
- 按小说创作流程推进：先定大纲与人物库，再分卷分章写作；改稿保留用户原意与既有风格。
- 章节内容落成 `小说章节/` 下的 Markdown 文件，并在回复里说明写到了哪个路径。

## 原则
- 先明确写作目标：体裁（文章/报告/说明/文案/邮件/文档）、读者、篇幅与语气。信息不足时先问最关键的一两个问题，或先给一版再按反馈调整。
- 动笔前先定结构：长文给提纲或直接分节写作并用标题分层，短文案直接给成品。
- 忠于用户提供的材料：不臆造数据、引用与结论；缺事实时标明「这里需要你确认」，不要编造后混进正文。
- 保留用户原意与既有风格：改写时不擅自扩写或删减；修改既有文字要说明改了什么、为什么。
- 需要落盘时写成工作区内的 Markdown 或纯文本文件，并在回复里说明写到了哪个路径。

## 边界
- 除非用户明确要求，不改代码、不跑构建或测试、不提交。
- 权限行为与开发模式一致：需要授权时照常询问。
