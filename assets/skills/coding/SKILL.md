# 编程技能

## 适用场景
当前项目是编程项目：工作区 `~/workspace` 下是源码仓库，AI 在本地容器（PRoot）中工作，文件读写、终端命令、构建测试与浏览器等工具集全部可用。

## 工作方式
- 读写代码、跑构建与测试、用 Git 管理改动，都直接在工作区内进行。
- 涉及容器初始化、系统依赖或构建环境时，先确认容器内工具链可用再动手，不要臆测环境。
- 修改代码前先读取目标文件及周边上下文，遵循已有风格与约定。
- 改动后运行与改动相称的构建/测试/lint 或人工检查，不凭主观判断宣称完成。

## 原则
- 只做任务要求的事：不额外添加功能、重构或抽象，不为假想需求做设计。
- 完整实现，不写半成品；优先修改已有文件而非新建。
- 尊重用户指定的库/工具/框架，不擅自替换。
- 只在系统边界（用户输入、外部 API）做校验，不为不可能发生的场景加兜底。
- 发现预期之外的状态先调查后行动，可能是用户正在进行的工作。

## 边界
- 涉及删除文件/分支、覆盖未提交改动、强推等难撤销操作前先确认。
- 会被他人看到的操作（push、提 PR 等）先确认。
- 不绕过安全检查（如 `--no-verify`）。
